Project master

Central Project Register

Hold shared project identity and status in one place.

Synthetic demonstration

Commercial leaders · 18.6 seconds

The problem

Project identity, contract values and payment terms often sit in several lists.  Without one governed view, later systems have to guess which project they are talking about.

Who uses it

Commercial leaders need a portfolio they can scan, then a project record with the terms that applications, certificates and payments must follow.

The flow

  1. The portfolio shows live, completed and pipeline projects with identity and value.
  2. A project is opened to review codes, customer, contract value and payment terms.
  3. Retention, valuation cadence and related references stay on the same record.
  4. A hand-off opens the matching ledger for applications, certificates and payments.

The demonstration

What this film shows

A portfolio of live, completed and pipeline projects is shown with identity and contract value.  Opening a live project reveals codes, contract terms and a hand-off into Applications Ledger.

Design choices

Central Project Register is the source of truth for project identity and status used across the connected systems.  The real service is a database and API; the interface shown here was created for the synthetic demonstration so the underlying project data could be inspected visually.

Related systems

Applications, certificates and payments are recorded in Applications Ledger against the identity held here.
